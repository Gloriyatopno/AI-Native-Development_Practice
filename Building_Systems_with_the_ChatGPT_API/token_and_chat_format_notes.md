Language models can be used for:

- Answering questions

- Classifying information
- Generating code
- Creating structured responses
- Extracting information from text

# 2. Chat Format

Chat-based language models receive messages using different roles.

The main roles are:

- `system`
- `user`
- `assistant`

## 2.1 System Message

The system message defines the assistant's behavior, rules, and instructions.

Example:

```python
{
    "role": "system",
    "content": "You are a helpful classification assistant."
}
```

The system message is useful for:

- Defining the assistant's role
- Giving instructions
- Setting response rules
- Defining categories
- Specifying the required output format

## 2.2 User Message

The user message contains the actual question, request, or input.

Example:

```python
{
    "role": "user",
    "content": "Classify this customer query."
}
```

In a classification workflow, the user message contains the customer query that needs to be classified.

## 2.3 Assistant Message

The assistant message contains the response generated by the language model.

Example:

```python
{
    "role": "assistant",
    "content": "Account Management"
}
```

## 2.4 Example Chat Format

```python
messages = [
    {
        "role": "system",
        "content": "You are a helpful assistant."
    },
    {
        "role": "user",
        "content": "What is an API?"
    }
]
```

The model uses the system message and user message to generate a response.

# 3. Chat Completions API

The Chat Completions API accepts a list of messages and generates a response from the language model.

Example using Groq:

```python
response = client.chat.completions.create(
    model=MODEL,
    messages=messages,
    temperature=0,
    max_tokens=150
)
```

The response can be accessed using:

```python
content = response.choices[0].message.content
```

The main parts of the request are:

| Parameter | Description |
|---|---|
| `model` | Specifies the language model to use |
| `messages` | Contains system, user, and assistant messages |
| `temperature` | Controls the randomness of the response |
| `max_tokens` | Limits the maximum number of output tokens |

# 4. Tokens

Tokens are small units of text processed by a language model.

A token may be:

- A complete word
- Part of a word
- A punctuation mark
- A space or text fragment

For example:

```text
Hello, world!
```

The model divides text into smaller units called tokens before processing it.

## 4.1 Why Tokens Matter

Tokens are important because:

- Models have token limits.
- Input tokens affect usage.
- Output tokens affect usage.
- Longer prompts use more tokens.
- Large conversations may use many tokens.
- Token usage can affect API costs.
- `max_tokens` limits the generated output length.

## 4.2 Input and Output Tokens

### Input Tokens

Input tokens are the tokens sent to the model.

They include:

- System instructions
- User messages
- Previous conversation messages

### Output Tokens

Output tokens are the tokens generated by the model in its response.

Example:

```python
response = client.chat.completions.create(
    model=MODEL,
    messages=messages,
    temperature=0,
    max_tokens=150
)
```

Here:

```python
max_tokens=150
```

sets the maximum number of tokens that the model can generate in the response.

The actual response may contain fewer than 150 tokens.

# 5. Temperature

Temperature controls the randomness and variety of the model's response.

## 5.1 Low Temperature

A low temperature produces more consistent and predictable responses.

Example:

```python
temperature=0
```

This is useful for:

- Classification
- Data extraction
- JSON output
- Repeated testing
- Customer support routing

## 5.2 Higher Temperature

A higher temperature can produce more varied and creative responses.

Example:

```python
temperature=1
```

This is useful for:

- Creative writing
- Poems
- Stories
- Brainstorming
- Creative ideas

## 5.3 Temperature Used in This Project

For classification, the following value was used:

```python
temperature=0
```

This helps the model return more consistent classifications.

# 8. Classification Using System and User Messages

The system message contains the classification rules.

The user message contains the customer query.

Example:

```python
messages = [
    {
        "role": "system",
        "content": """
Classify customer queries into:
- Billing
- Technical Support
- Account Management
- General Inquiry

Return only the primary category.
"""

    {
        "role": "user",
        "content": "How can I reset my password?"
    }
]
```

Expected response:

```text

```

The query is classified as `Account Management` because password reset is related to account management.

# 9. Structured JSON Output

Structured output makes the model's response easier for programs to process.

Instead of returning a long explanation, the model returns data in a fixed format.

Example:

```json
{
    "primary": "Account Management",
    "secondary": "Password reset"
}
```

The JSON response contains:

- `primary`: The main category
- `secondary`: The more specific category

## 9.1 Python JSON Processing

The Python `json` library can be used to process the response.

Example:

```python
import json

classification = json.loads(response)

print(classification["primary"])
print(classification["secondary"])
```

Output:

```text
Account Management
Password reset
```

Structured JSON is useful because the response can be used by another program, database, or application.

# 10. Delimiters in Prompts

A delimiter is a special character or sequence used to separate instructions from user-provided text.

Example:

```python
delimiter = "####"
```

The customer query can be placed between delimiters:

```python
user_message = f"{delimiter}{customer_query}{delimiter}"
```

Example input:

```text
####I want to delete my profile and all of my user data####
```

Delimiters help clearly separate the customer query from the system instructions.

They are useful when:

- The input contains multiple lines
- The input may contain instructions
- The prompt contains multiple sections
- User-provided text must be clearly separated

# 15. Important Prompting Techniques

Useful prompting techniques include:

- Clearly define the task.
- Provide the allowed categories.
- Explain the expected output format.
- Use system messages for rules and instructions.
- Use user messages for actual input.
- Use delimiters to separate instructions and user text.
- Use low temperature for consistent classification.
- Use JSON when the output will be processed by code.
- Use `max_tokens` to limit response length.
- Keep prompts clear and specific.
- Avoid unnecessary instructions.
